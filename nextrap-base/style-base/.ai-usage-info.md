# @nextrap/style-base

## Purpose

Provides the global Nextrap design-token contract. The runtime theme emits defaults and derives related CSS variables entirely from CSS custom properties, so an external theme can override inputs without recompiling Nextrap.

Use this package once at document/theme level. Components consume `var(--nt-*)`; they should not depend on private Sass theme maps.

## Runtime theme (preferred)

```scss
@use '@nextrap/style-base' as nt;

:root {
  @include nt.runtime-theme();

  // Override only the values your product/theme owns.
  --nt-primary: #0057b8;
  --nt-neutral: #667085;
  --nt-radius: .5rem;
}
```

`@nextrap/style-base/default` emits the same runtime defaults directly. `theme()` / `create-theme()` remain for backward compatibility with Sass-based integrations.

## Token usage contract

### Brand and state inputs

| Variable | Intended usage |
|---|---|
| `--nt-primary` | Main brand/action color: primary buttons, selected states, key actions. |
| `--nt-secondary` | Secondary actions and UI where primary emphasis would be too strong. |
| `--nt-tertiary` | Optional third brand/semantic family for differentiated groups or actions. |
| `--nt-accent` | Highlights and complementary brand emphasis. |
| `--nt-success` | Positive states, confirmations and completed outcomes. |
| `--nt-info` | Informational notices, callouts and neutral status UI. |
| `--nt-warning` | Cautionary states that need attention but are not errors. |
| `--nt-danger` | Destructive actions, validation errors and critical states. |
| `--nt-neutral` | Neutral seed used to derive surfaces, text, borders and the gray ramp. |
| `--nt-light` / `--nt-dark` | Explicit light/dark utility colors where a semantic surface is not appropriate. |
| `--nt-white` / `--nt-black` | Absolute contrast endpoints and explicit white/black usage. |

Each semantic color family automatically provides `-hover`, `-active`, `-subtle` and `-emphasis` variants. Use `-hover`/`-active` for interaction feedback, `-subtle` for tinted backgrounds and `-emphasis` for stronger borders/text/details.

`--nt-text-on-primary`, `--nt-text-on-secondary`, `--nt-text-on-tertiary`, `--nt-text-on-accent`, `--nt-text-on-success`, `--nt-text-on-info`, `--nt-text-on-warning`, `--nt-text-on-danger`, `--nt-text-on-light`, `--nt-text-on-dark`, `--nt-text-on-white` and `--nt-text-on-black` are foreground colors for content rendered directly on the corresponding background.

### Surfaces and content

| Variable | Intended usage |
|---|---|
| `--nt-surface` | Default page or component background. |
| `--nt-surface-muted` | Recessed/secondary areas, grouped content and subtle panels. |
| `--nt-surface-raised` | Cards, popovers, dialogs and visually elevated surfaces. |
| `--nt-text` | Default readable foreground text. |
| `--nt-text-muted` | Descriptions, metadata, helper text and secondary copy. |
| `--nt-header` | Heading foreground where headings need a theme-specific color. |
| `--nt-border` | Standard component borders and dividers. |
| `--nt-focus` | Keyboard/focus-visible rings and accessibility focus indicators. |
| `--nt-link` | Default link foreground. |
| `--nt-link-hover` | Link hover feedback. |
| `--nt-link-active` | Pressed/active link feedback. |

### Typography

| Variable | Intended usage |
|---|---|
| `--nt-font-family` | Default body and control font family. |
| `--nt-font-family-header` | Heading/display family; defaults to the base family. |
| `--nt-font-size` | Base text size and reference for the text scale. |
| `--nt-font-size-header` | Maximum heading size (`h1`); heading scale interpolates down from it. |
| `--nt-font-size-small` | Captions, metadata, helper and supporting text. |
| `--nt-font-weight-base` | Normal body/control weight. |
| `--nt-font-weight-header` | Default heading weight. |
| `--nt-font-weight-bold` | Strong emphasis/bold weight. |
| `--nt-line-height` | Body/control line height and text-rhythm baseline. |
| `--nt-line-height-header` | Compact heading/display line height. |

`--nt-fs-1 … --nt-fs-6` form the automatically derived general text scale. `--nt-fs-h1 … --nt-fs-h6` form the heading scale. Prefer these when a component needs a shared scale step instead of inventing a local font size.

### Shape

| Variable | Intended usage |
|---|---|
| `--nt-radius` | Theme-level base radius. Override this to change the overall roundness of the UI. |
| `--nt-border-radius-sm` | Tags, badges, compact controls and other small elements. |
| `--nt-border-radius` | Default component radius; compatibility alias of `--nt-radius`. |
| `--nt-border-radius-xl` | Large cards, dialogs, panels and prominent surfaces. |
| `--nt-border-width` | Standard component/divider border thickness. |

## Spacing system

### Primitive spacing

`--nt-space-0 … --nt-space-10` are the shared primitive scale. Use a primitive when an exact scale step is intentionally part of a component's design contract. Application/layout code should normally prefer the semantic tokens below.

| Variable | Default | Typical usage |
|---|---:|---|
| `--nt-space-0` | `0` | Reset/no spacing. |
| `--nt-space-1` | `.25rem` | Micro gaps and tiny icon adjustments. |
| `--nt-space-2` | `.5rem` | Tight icon/text gaps and compact internals. |
| `--nt-space-3` | `.75rem` | Small control spacing/padding reference. |
| `--nt-space-4` | `1rem` | Normal text rhythm and common base gaps. |
| `--nt-space-5` | `1.5rem` | Component padding and container gutter reference. |
| `--nt-space-6` | `2rem` | Gaps between sibling components/content regions. |
| `--nt-space-7` | `3rem` | Compact major-section separation. |
| `--nt-space-8` | `4rem` | Major layout/section separation. |
| `--nt-space-9` | `6rem` | Large page-section separation. |
| `--nt-space-10` | `8rem` | Hero and maximum standard page-region spacing. |

### Semantic spacing — preferred

| Variable | Scope | Use for | Do not primarily use for |
|---|---|---|---|
| `--nt-spacing-text` | Typography/content | Vertical rhythm between paragraphs, lists, prose blocks, stacked labels and related textual elements. | Card padding or page sections. |
| `--nt-spacing-control` | Controls | Button/input internal spacing reference, icon-to-label gaps, compact toolbars and gaps between tightly related controls. | General card padding or page layout. |
| `--nt-spacing-component` | Component internals | Card/dialog/panel padding and spacing between regions that belong to the same component. | Distance between independent cards/sections. |
| `--nt-spacing-layout` | Layout composition | Grid/flex gaps between sibling components, cards, columns and independent content regions. | Internal button/input spacing. |
| `--nt-spacing-section` | Page composition | Vertical separation between major page sections, landing-page bands and large content chapters. It is fluid by default. | Component internals. |

A useful mental model is: **text → control → component → layout → section**. Moving right increases both visual distance and structural scope.

Example:

```css
.article-copy > * + * {
  margin-block-start: var(--nt-spacing-text);
}

.toolbar {
  gap: var(--nt-spacing-control);
}

.card {
  padding: var(--nt-spacing-component);
}

.card-grid {
  gap: var(--nt-spacing-layout);
}

.page-section + .page-section {
  margin-block-start: var(--nt-spacing-section);
}
```

## Container

| Variable | Intended usage |
|---|---|
| `--nt-container-max` | Maximum width of centered page/content containers. |
| `--nt-container-gutter` | Horizontal inset between container content and viewport edge. |
| `--nt-container-width` | Legacy computed responsive width; prefer `max` + `gutter` in new code. |

```css
.container {
  width: min(
    calc(100% - 2 * var(--nt-container-gutter)),
    var(--nt-container-max)
  );
  margin-inline: auto;
}
```

## Neutral gray scale

`--nt-gray-100 … --nt-gray-900` are derived from `--nt-neutral`. Use them for neutral component details when the semantic `surface`, `text`, `text-muted` or `border` tokens do not express the required intent. `100` is the lightest ramp step, `600` is the neutral seed and `900` is the darkest ramp step. Prefer semantic tokens whenever one fits.

## Compatibility aliases

These remain available for existing packages but new integrations should use the semantic/public name:

- `--nt-body` → `--nt-surface`
- `--nt-body-secondary` → `--nt-surface-muted`
- `--nt-body-tertiary` → `--nt-surface-raised`
- `--nt-background` → `--nt-surface`
- `--nt-font-family-base` → `--nt-font-family`
- `--nt-font-size-base` → `--nt-font-size`
- `--nt-line-height-base` → `--nt-line-height`
- `--nt-border-radius` → `--nt-radius`
- `--nt-container-width` → use `--nt-container-max` + `--nt-container-gutter`

Additional compatibility tokens such as `--nt-font-size-root`, `--nt-link-on-dark`, `--nt-text-decoration-link`, `--nt-gray-dark` and `--nt-scroll-padding-top` exist for older Nextrap consumers and should generally not be the first choice for new component APIs.

## Architecture contract

- `@nextrap/style-base` is a token layer, not a component stylesheet.
- Include it once at document/theme level; do not include it inside component shadow-DOM styles.
- `@nextrap/style-base/default` uses the same runtime token engine and must stay visually side-effect free.
- Components consume `var(--nt-*)`; cross-package interoperability must not depend on private Sass maps.
- Runtime input tokens are the theme override surface; derived tokens should normally be left to the engine.
- Do not emit resets, native-element styling, utility classes or component styling from style-base.
