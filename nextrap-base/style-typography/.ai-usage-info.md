# @nextrap/style-typography

## Purpose

Provides typography/prose styling primitives for native text elements and rich-text contexts. Typography owns text rhythm and visual treatment; it does not own page, section or component layout.

## Usage contract

- Follow `docs/style-packages-architecture.md`.
- `index.scss` is the Sass API entry; `default.scss` is the explicit default CSS output entry.
- Public classes should map to same-named mixins where meaningful.
- Mixins must remain composable on arbitrary selectors/scopes for theme/component semantic mapping.
- Consume public `--nt-*` runtime tokens from `@nextrap/style-base`; do not depend on private cross-package Sass internals.
- Normal text elements must inherit their foreground color from the containing context. Do not set `--nt-text` directly on headings, paragraphs, lead text or preformatted blocks, because doing so breaks semantic `surface-*` foreground inheritance.
- For lower-emphasis text use `--nt-surface-text-muted` when present and fall back to `--nt-text-muted`. Do not use palette tokens such as `--nt-dark-subtle` as semantic text fallbacks.
- Links use `--nt-surface-link` / `--nt-surface-link-hover` when supplied by a local surface, otherwise `--nt-link` / `--nt-link-hover`.
- Typography-specific spacing tokens are valid semantic overrides, but their defaults should derive from the central `--nt-space-*` scale where practical.
- Interactive typography (especially links) must use the shared `--nt-transition-duration`, `--nt-transition-easing`, `--nt-focus-ring-width` and `--nt-focus-ring-offset` runtime tokens rather than hard-coded timing values.

## Surface integration

`@nextrap/style-utils` semantic `surface-*` helpers establish an inherited local typography context:

- `--nt-surface-text` — readable foreground for the active surface.
- `--nt-surface-text-muted` — readable lower-emphasis foreground.
- `--nt-surface-link` — local link foreground.
- `--nt-surface-link-hover` — optional local hover foreground.

Typography should consume this context through normal CSS inheritance/fallbacks rather than detecting concrete surface classes or semantic colors itself. This keeps typography independent from `primary`, `dark`, `warning`, etc. and allows custom theme surfaces to provide the same contract.
