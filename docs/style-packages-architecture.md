# Nextrap `@nextrap/style-*` package architecture

This document defines the repository-wide contract for current and future Nextrap style packages.

> **Authoritative source for coding agents:** The [Nextrap skill](`../.agents/skills/nextrap-skill/SKILL.md`) contains the same rules and is loaded automatically. This document is the detailed reference.

---

## 1. Package responsibilities and boundaries

| Package | Role | Allowed |
|---|---|---|
| `@nextrap/style-base` | Token-only: `--nt-*` custom properties, theme generation | CSS custom properties only — no visual rules |
| `@nextrap/style-utils` | Atomic utility mixins/classes (spacing, display, flex, colors, …) | Single-property or tightly related property groups |
| `@nextrap/style-elements` | Reusable visual element patterns | Multi-property patterns: prose, table, list-group, container |
| `@nextrap/style-typography` | Base typographic rules (headings, body, links, …) | Global typographic defaults; prose via `style-elements` |
| `style-button` (and future specialized) | Own a specific component/pattern | Follow same entry-point and mixin contract |
| Web component SCSS (Shadow DOM) | Only minimal functional Shadow DOM styles | `@nextrap/style-reset` only; theming through `::part()` |

The boundaries:
- `style-utils` does NOT own multi-property element patterns (→ `style-elements`).
- `style-elements` does NOT own atomic single-property utilities (→ `style-utils`).
- `style-base` does NOT own visual rules of any kind.
- Web component Shadow DOM does NOT use `@nextrap/style-base` or any non-reset global styles.

---

## 2. Entry-point contract: `index.scss` vs `default.scss`

Every style package separates Sass API from CSS output:

- **`index.scss`** = Sass API only. Importing it must **not** emit global visual CSS.
- **`default.scss`** = explicit, ready-to-use CSS class output generated from the public mixins.

```scss
@use '@nextrap/style-elements' as e;        // API — no CSS emitted
@use '@nextrap/style-elements/default';     // Materializes default CSS classes
```

Package `exports` in `package.json` must consistently expose both entry points:

```json
{
  "exports": {
    ".": "./index.scss",
    "./default": "./default.scss"
  }
}
```

## 3. CSS class ↔ Sass mixin naming convention (1:1 parity)

Where technically meaningful, every public CSS class has a public Sass mixin with **exactly the same name without the leading dot**:

```text
.table                   ↔ table()
.table-striped           ↔ table-striped()
.table-bordered          ↔ table-bordered()
.prose                   ↔ prose()
.prose-xl                ↔ prose-xl()
.list-group              ↔ list-group()
.list-group-flush        ↔ list-group-flush()
.container               ↔ container()
.container-fluid         ↔ container-fluid()
.d-flex                  ↔ d-flex()
.gap-3                   ↔ gap-3()
.mt-2                    ↔ mt-2()
.text-primary            ↔ text-primary()
.bg-primary              ↔ bg-primary()
.btn                     ↔ btn()
.btn-primary             ↔ btn-primary()
.btn-outline-primary     ↔ btn-outline-primary()
```

CSS classes **must be generated by including the mixin** — never maintain a separate duplicate CSS implementation:

```scss
// default.scss
.table { @include table(); }
.table-striped { @include table-striped(); }
```

## 4. Base and modifier mixins are independently composable

Modifier mixins contain only their modifier behavior and **do not implicitly include the base mixin**:

```scss
@mixin table() {
  width: 100%;
  border-collapse: collapse;
}

@mixin table-striped() {
  // only modifier behavior — does NOT call table()
  tbody tr:nth-child(odd) {
    background: var(--nt-table-stripe-bg, rgba(0, 0, 0, 0.05));
  }
}

@mixin table-bordered() {
  // only modifier behavior
  & > :not(caption) > * > * {
    border-width: var(--nt-border-width, 1px);
  }
}
```

HTML usage is conceptually identical to composing mixins in Sass:

```html
<table class="table table-striped table-bordered">
```

```scss
.theme table {
  @include e.table();
  @include e.table-striped();
  @include e.table-bordered();
}
```

The same applies to buttons, list groups, utilities, and all future style packages.

---

## 5. Mixins style the current selector (no root-selector ownership)

Public style mixins must not own their root selector. They apply declarations and relative child/state selectors to the selector where they are included:

```scss
.customer-theme {
  table {
    @include e.table();
    @include e.table-striped();
  }

  button {
    @include e.btn();
    @include e.btn-outline-primary();
  }

  nav > ul {
    @include e.list-group();
    @include e.list-group-flush();
  }

  .special-box {
    @include u.d-flex();
    @include u.gap-3();
    @include u.mt-2();
  }
}
```

Generated selectors must remain under the caller's scope. Do not escape with `@at-root` inside public mixins without a specifically documented exceptional reason.

## 6. `style-base` is token-only and visually side-effect free

This is a hard interoperability requirement.

`@nextrap/style-base` must be safe to load on **any page**, including Bootstrap, Tailwind-based systems, Material, CMS themes, legacy CSS, or unrelated custom frameworks.

**Allowed** (only `--nt-*` CSS custom properties):
```css
:root {
  --nt-primary: ...;
  --nt-text: ...;
  --nt-space-1: ...;
  --nt-radius: ...;
}
```

**Not allowed** in `style-base`:
```css
* { box-sizing: border-box; }
body { margin: 0; }
button { font: inherit; }
a { color: var(--nt-link); }
h1 { font-size: ...; }
```

This must be safe:
```scss
@use 'bootstrap';
@use '@nextrap/style-base/default';
// Bootstrap page must be visually unchanged
```

## 7. Cross-package interoperability via `--nt-*` tokens

Style packages communicate through `--nt-*` CSS custom properties rather than private Sass imports from sibling packages:

```scss
// Preferred
color: var(--nt-text, currentColor);
padding: var(--nt-space-3, .75rem);
border-radius: var(--nt-border-radius, 0.375rem);

// Avoid
@use '../../../style-base/variables';  // ← private coupling, forbidden
@use '../../../style-base/functions';  // ← private coupling, forbidden
```

`style-elements` and `style-utils` must compile without importing any Sass internals from `style-base`.

---

## 8. Derived themes compose mixins onto semantic selectors

A derived theme may intentionally style native/semantic markup without adding Nextrap classes to the HTML:

```scss
@use '@nextrap/style-base' as nt;
@use '@nextrap/style-elements' as e;
@use '@nextrap/style-utils' as u;

.theme-corporate {
  @include nt.theme((primary: #0057b8, neutral: #667085));

  table {
    @include e.table();
    @include e.table-striped();
  }

  button {
    @include e.btn();
    @include e.btn-primary();
  }

  nav > ul {
    @include e.list-group();
    @include e.list-group-flush();
  }

  .card-header {
    @include u.d-flex();
    @include u.gap-3();
    @include u.mt-2();
    @include u.text-primary();
  }
}
```

The exact same mixins that generate the default classes are reused here — no separate native-element implementation is needed.

## 9. Naming conventions

| Kind | Pattern | Examples |
|---|---|---|
| Token (CSS custom property) | `--nt-<token>` | `--nt-primary`, `--nt-space-3`, `--nt-border-radius`, `--nt-gray-500` |
| Local element variable | `--<element>-<prop>` | `--prose-max-w`, `--prose-para-space`, `--table-stripe-bg` |
| Base class / mixin | lowercase, hyphenated | `.table` / `table()`, `.prose` / `prose()`, `.btn` / `btn()` |
| Modifier class / mixin | `<base>-<modifier>` | `.table-striped` / `table-striped()`, `.btn-primary` / `btn-primary()` |
| Utility class / mixin | short atomic name | `.d-flex` / `d-flex()`, `.mt-2` / `mt-2()`, `.gap-3` / `gap-3()` |
| Gray scale | `{prefix}-gray-{100–900}` | `.bg-gray-500`, `.text-gray-100` |
| Component style variant | `style-<name>` | `style-default`, `style-testimonial` |
| Feature modifier (web components) | `with-<feature>` | `with-background-and-divider` |

## 10. Checklist for creating or modifying a style package

- [ ] `index.scss` exposes only Sass API (mixins/forwards) — no CSS on `@use`.
- [ ] `default.scss` materializes CSS classes by including the mixins — no standalone CSS.
- [ ] `package.json` exports both `.` (index.scss) and `./default` (default.scss).
- [ ] Every public class has a corresponding mixin with the same name (without `.`).
- [ ] Modifier mixins do not silently include their base mixin.
- [ ] Mixins do not hard-code their own root selector.
- [ ] No private Sass imports from sibling packages (use `--nt-*` vars instead).
- [ ] `style-base` is not modified to add visual rules.
- [ ] Package SCSS compiles cleanly with `sass`.
