# Nextrap `@nextrap/style-*` package architecture

This document defines the repository-wide contract for current and future Nextrap style packages.

## 1) Entry-point contract

- `index.scss` is the **Sass API** entry point.
- `default.scss` is the **explicit CSS output** entry point.

```scss
@use '@nextrap/style-x' as x; // API usage (mixins/functions/forwards)
@use '@nextrap/style-x/default'; // class output usage
```

`default.scss` must materialize class output from the same mixins exposed by `index.scss`.

## 2) Class ↔ mixin parity

Where technically meaningful, every public class has a same-named mixin (without the dot):

- `.btn` ↔ `btn()`
- `.btn-primary` ↔ `btn-primary()`
- `.table-striped` ↔ `table-striped()`
- `.d-flex` ↔ `d-flex()`

Classes must be generated by including the mixin, not by duplicate implementations.

## 3) Composition rules

- Base mixins and modifier mixins stay independently composable.
- Modifier mixins must not silently include base mixins.
- Mixins must style the **current selector** (no forced root selector ownership).

This must work inside arbitrary scopes:

```scss
.customer-theme {
  table {
    @include e.table();
    @include e.table-striped();
  }
}
```

## 4) Package responsibilities

- `@nextrap/style-base`: tokens, theme generation, `--nt-*` custom properties.
- `@nextrap/style-utils`: atomic utility styles.
- `@nextrap/style-elements`: reusable visual element patterns.
- Specialized packages (for example `style-button`) follow the same entry-point and class/mixin contract.

## 5) Critical `style-base` rule

`@nextrap/style-base` is token-only and must remain visually side-effect free.

Allowed:

- CSS custom property declarations in intended theme scopes.

Not allowed:

- reset/normalize rules
- global typography defaults
- native element styling (`body`, `a`, `button`, `table`, ...)
- utility/component/layout class styling

`@nextrap/style-base/default` must also stay token-only.

## 6) Cross-package interoperability

- Prefer `var(--nt-*)` custom properties for integration between style packages.
- Avoid importing private Sass internals across sibling packages.

## 7) Theme/application composition

Theme packages map semantic/native selectors intentionally, for example:

```scss
.theme-corporate {
  @include nt.theme((primary: #0057b8));

  button {
    @include b.btn();
    @include b.btn-primary();
  }
}
```

Mapping plain native selectors to Nextrap style primitives belongs to theme/application layers, not to token-only base layers.
