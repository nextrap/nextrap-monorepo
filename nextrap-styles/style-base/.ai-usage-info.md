# @nextrap/style-base

## Purpose

Provides the global Nextrap design-token contract. There is exactly one theme engine and one public theming mixin: `runtime-theme()`. It emits defaults, derived CSS custom properties and light/dark switching support without Sass theme maps or compile-time theme generation.

Materialisiere die Theme-Tokens einmal auf Dokument-/Theme-Ebene. Komponenten
konsumieren `var(--nt-*)` und dürfen keine privaten Sass-Theme-Interna verwenden.
Die Kontrastberechnung ist intern und keine öffentliche Sass-API für Komponenten.

## Theme creation contract

### Standard/default theme

```scss
@use '@nextrap/style-base/default';
```

`default.scss` emits `runtime-theme()` on `:root`. No second mixin or scheme setup is required.

### Custom theme

```scss
@use '@nextrap/style-base' as nt;

:root {
  @include nt.runtime-theme();

  // Theme-owned inputs come after the mixin.
  --nt-primary: light-dark(#0057b8, #65b7ff);
  --nt-neutral: #667085;
  --nt-text: light-dark(#4c4c4c, #d2d2d2);
  --nt-radius: .5rem;
  --nt-font-family: Inter, sans-serif;
}
```

Always emit `runtime-theme()` first and declare theme overrides afterwards in the same scope. Do not copy the generated token graph into a theme repository. Override the smallest set of input variables the theme actually owns; derived tokens then update automatically.

A derived variable may be overridden only when the design intentionally differs from the standard derivation. `--nt-text` is the normal theme-level foreground override; `--nt-header` inherits it by default and should only be set separately when the design intentionally gives headings another color.

### External theme repository

An external theme package should depend on `@nextrap/style-base`, call `runtime-theme()` in its theme scope, and contain only its owned CSS-variable overrides. This keeps the external theme automatically compatible when style-base adds or fixes derived tokens.

### Scoped themes

`runtime-theme()` can be emitted on `:root`, a theme class or another ancestor scope. All descendant Nextrap components inherit the resulting `--nt-*` contract.

### Color schemes

Light and dark are schemes of the same theme, not separate theme definitions.

`runtime-theme()` includes all switching support. With no `data-nt-scheme` attribute, `color-scheme: light dark` follows the operating-system preference. To force a scheme, set `data-nt-scheme="light"` or `data-nt-scheme="dark"` on the document or another ancestor. Remove the attribute to return to OS preference.

Theme inputs that differ between schemes should use `light-dark()`. The first value is used in light mode and the second in dark mode; the active value follows the current `color-scheme`, including manual `data-nt-scheme` changes:

```css
--nt-primary: light-dark(#0057b8, #65b7ff);
--nt-accent: light-dark(#d79b35, #f0b95c);
--nt-text: light-dark(#4c4c4c, #d2d2d2);
```

`--nt-header` follows `--nt-text` automatically in both schemes. Only add a separate `--nt-header: light-dark(..., ...);` override when headings intentionally need a different foreground.

Application switching example:

```js
document.documentElement.dataset.ntScheme = 'dark';
document.documentElement.dataset.ntScheme = 'light';
delete document.documentElement.dataset.ntScheme;
```

Do not introduce or call a separate scheme-switcher mixin.

## Token usage contract

### Brand and state inputs

| Variable | Intended usage |
|---|---|
| `--nt-primary` | Main brand/action color: primary buttons, selected states, key actions. |
| `--nt-secondary` | Secondary actions and UI where primary emphasis would be too strong. |
| `--nt-tertiary` | Optional third brand/semantic family for differentiated groups or actions. |
| `--nt-accent` | Highlights and complementary brand emphasis. |
| `--nt-success` | Positive states, confirmations and completed outcomes. |
| `--nt-info` | Informational notices, callouts and neutral status UI. |
| `--nt-warning` | Cautionary states that need attention but are not errors. |
| `--nt-danger` | Destructive actions, validation errors and critical states. |
| `--nt-neutral` | Neutral seed used to derive surfaces, text, borders and the gray ramp. |
| `--nt-light` / `--nt-dark` | Explicit light/dark utility colors where a semantic surface is not appropriate. |
| `--nt-white` / `--nt-black` | Absolute contrast endpoints and explicit white/black usage. |

Each semantic color family provides `-hover`, `-active`, `-subtle` and `-emphasis` variants. Use `-hover`/`-active` for interaction feedback, `-subtle` for tinted backgrounds and `-emphasis` for stronger borders/text/details.

Die Familien `primary`, `secondary`, `tertiary`, `accent`, `success`, `info`,
`warning`, `danger`, `light`, `dark`, `white` und `black` liefern jeweils einen
Basis-Kontrastvordergrund `--nt-text-on-<family>` für Inhalt direkt auf
`--nt-<family>`. Es gibt keine zusätzlichen globalen Text-Tokens pro Zustand.

Die vollständige CSS-Berechnung dieser Basis-Tokens bevorzugt Weiß ab `4.5:1`,
sonst Schwarz. Sie verwendet `color(srgb-linear ...)` und die relative Luminanz
`L = 0.2126 × R + 0.7152 × G + 0.0722 × B` nach
[WCAG 2.2](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html).
Die Schwellenprüfung wird nicht vorab gerundet; `round(up)` dient erst danach
der binären Auswahl. Ein privater Sass-Helper erzeugt den CSS-Ausdruck; die
Berechnung bleibt im Browser und folgt den aktuellen Theme-Werten.

Die Fallback-Reihenfolge ist verbindlich:

1. Statische Schwarz-/Weißwerte zur Standardpalette.
2. Natives [contrast-color()](https://www.w3.org/TR/css-color-5/#contrast-color)
   innerhalb seiner `@supports`-Prüfung.
3. Die exakte Weißpräferenz, wenn `@supports` den vollständigen relativen
   Farbausdruck einschließlich der Auswahlberechnung unterstützt.

Die Standard-Primary-Farbe ist `#0969da` mit rund `5.19:1` für weißen Text.
Success, Tertiary, Info und Warning benötigen auf ihren Standard-Basisflächen
Schwarz; Warning erreicht damit rund `12.88:1`.

Statische Fallbacks garantieren keinen Kontrast für beliebige Theme-Overrides.
Die Berechnung gilt für deckende sRGB-Flächen. Transparenz erfordert den
tatsächlichen Backdrop, Wide-Gamut-Farben eine eigene Prüfung. Daraus folgt
keine allgemeine Barrierefreiheitsgarantie für eine Komponente oder Seite.

### Komponenten-Zustände

Komponenten beziehen die Basis-Kontrastfarben ausschließlich über CSS Custom
Properties. Ihre Zustandsdarstellung benötigt weder Sass-Imports von `style-base`
noch eine Kopie der internen Formel. Zustandsflächen und passende Fallbacks
gehören zum jeweiligen Komponenten-Style.

`style-button` verwendet bei gefüllten Buttons denselben Basis-Kontrasttoken
für Normal, Hover und Active. Die Hintergründe wechseln, die bereitgestellte
Textfarbe bleibt gleich. Das Theme muss daher einen Vordergrund liefern, der
zu allen drei Flächen passt; der Button enthält keine eigene Kontrastberechnung.

### Surfaces and content

| Variable | Intended usage |
|---|---|
| `--nt-surface` | Default page or component background. |
| `--nt-surface-muted` | Recessed/secondary areas, grouped content and subtle panels. |
| `--nt-surface-raised` | Cards, popovers, dialogs and visually elevated surfaces. |
| `--nt-text` | Default body/control foreground; defaults to `#4c4c4c` in light mode and `#d2d2d2` in dark mode. |
| `--nt-text-muted` | Descriptions, metadata, helper text and secondary copy; derived from `--nt-text` and `--nt-surface`. |
| `--nt-header` | Heading foreground; defaults to `var(--nt-text)` and therefore follows the same light/dark value unless explicitly overridden. |
| `--nt-border` | Standard component borders and dividers. |
| `--nt-focus` | Keyboard/focus-visible rings and accessibility focus indicators. |
| `--nt-link` | Default link foreground. |
| `--nt-link-hover` | Link hover feedback. |
| `--nt-link-active` | Pressed/active link feedback. |

Normal typography must use `--nt-text`, `--nt-text-muted` and `--nt-header`, not `contrast-color()`. Override `--nt-text` after `runtime-theme()` to change the standard foreground for body text and headings together. Override `--nt-header` separately only when the design intentionally needs another heading color. Prefer `light-dark(<light>, <dark>)` so both schemes remain defined in one place and switch automatically with the active `color-scheme`.

Die interne automatische Kontrastwahl gilt für `--nt-text-on-*`. Normale Text-
und Überschriftenfarben folgen weiter dem expliziten Theme-Vertrag; sie werden
nicht pauschal durch eine Kontrastfunktion ersetzt.

### Typography

| Variable | Intended usage |
|---|---|
| `--nt-font-family` | Default body and control font family. |
| `--nt-font-family-header` | Heading/display family; defaults to the base family. |
| `--nt-font-size` | Base text size and reference for the text scale. |
| `--nt-font-size-header` | Maximum heading size (`h1`); heading scale interpolates down from it. |
| `--nt-font-size-small` | Captions, metadata, helper and supporting text. |
| `--nt-font-weight-base` | Normal body/control weight. |
| `--nt-font-weight-header` | Default heading weight. |
| `--nt-font-weight-bold` | Strong emphasis/bold weight. |
| `--nt-line-height` | Body/control line height and text-rhythm baseline. |
| `--nt-line-height-header` | Compact heading/display line height. |

`--nt-fs-1 … --nt-fs-6` form the derived general text scale. `--nt-fs-h1 … --nt-fs-h6` form the heading scale. Prefer them when a component needs a shared scale step instead of inventing a local size.

### Icons

Icon tokens contain monochrome SVG masks. Apply the token through `mask` or `mask-image` and set the visible color with `background-color`.

| Variable | Intended usage |
|---|---|
| `--nt-icon-close` | Generic dismiss/close icon. |
| `--nt-icon-close-sidebar` | Panel-close icon pointing left in its base orientation; rotate for other edges. |

### Shape

| Variable | Intended usage |
|---|---|
| `--nt-radius` | Theme-level base radius. Override this to change overall UI roundness. |
| `--nt-border-radius-sm` | Tags, badges, compact controls and other small elements. |
| `--nt-border-radius` | Default component radius derived from `--nt-radius`. |
| `--nt-border-radius-xl` | Large cards, dialogs, panels and prominent surfaces. |
| `--nt-border-width` | Standard component/divider border thickness. |

## Spacing system

### Primitive spacing

`--nt-space-0 … --nt-space-10` are the shared primitive scale. Use a primitive when an exact scale step is intentionally part of a component design contract. Application/layout code should normally prefer semantic tokens.

| Variable | Default | Typical usage |
|---|---:|---|
| `--nt-space-0` | `0` | Reset/no spacing. |
| `--nt-space-1` | `.25rem` | Micro gaps and tiny icon adjustments. |
| `--nt-space-2` | `.5rem` | Tight icon/text gaps and compact internals. |
| `--nt-space-3` | `.75rem` | Small control spacing/padding reference. |
| `--nt-space-4` | `1rem` | Normal text rhythm and common base gaps. |
| `--nt-space-5` | `1.5rem` | Component padding and container gutter reference. |
| `--nt-space-6` | `2rem` | Gaps between sibling components/content regions. |
| `--nt-space-7` | `3rem` | Compact major-section separation. |
| `--nt-space-8` | `4rem` | Major layout/section separation. |
| `--nt-space-9` | `6rem` | Large page-section separation. |
| `--nt-space-10` | `8rem` | Hero and maximum standard page-region spacing. |

### Semantic spacing — preferred

| Variable | Scope | Use for | Do not primarily use for |
|---|---|---|---|
| `--nt-spacing-text` | Typography/content | Vertical rhythm between paragraphs, lists, prose blocks, stacked labels and related textual elements. | Card padding or page sections. |
| `--nt-spacing-control` | Controls | Button/input internal spacing reference, icon-to-label gaps, compact toolbars and gaps between tightly related controls. | General card padding or page layout. |
| `--nt-spacing-component` | Component internals | Card/dialog/panel padding and spacing between regions belonging to the same component. | Distance between independent cards/sections. |
| `--nt-spacing-layout` | Layout composition | Grid/flex gaps between sibling components, cards, columns and independent content regions. | Internal button/input spacing. |
| `--nt-spacing-section` | Page composition | Vertical separation between major page sections, landing-page bands and large content chapters. | Component internals. |

Mental model: **text → control → component → layout → section**. Moving right increases visual distance and structural scope.

```css
.article-copy > * + * { margin-block-start: var(--nt-spacing-text); }
.toolbar { gap: var(--nt-spacing-control); }
.card { padding: var(--nt-spacing-component); }
.card-grid { gap: var(--nt-spacing-layout); }
.page-section + .page-section { margin-block-start: var(--nt-spacing-section); }
```

## Container

| Variable | Intended usage |
|---|---|
| `--nt-container-max` | Maximum width of centered page/content containers. |
| `--nt-container-gutter` | Horizontal inset between container content and viewport edge. |
| `--nt-container-width` | Computed responsive width for consumers that want a single ready-to-use width token. |

```css
.container {
  width: min(calc(100% - 2 * var(--nt-container-gutter)), var(--nt-container-max));
  margin-inline: auto;
}
```

## Neutral gray scale

`--nt-gray-100 … --nt-gray-900` are derived from `--nt-neutral`. Use them for neutral component details when `surface`, `text`, `text-muted` or `border` do not express the required intent. Prefer semantic tokens whenever one fits.

## Architecture contract

- There is one theme engine and one public theming mixin: `runtime-theme()`.
- `runtime-theme()` includes automatic OS scheme handling and manual `data-nt-scheme="light|dark"` switching.
- Do not introduce Sass theme maps, compile-time theme builders, separate scheme mixins or a parallel token generator.
- `@nextrap/style-base/default` must remain the ready-to-use standard theme.
- Theme-Tokens einmal auf Dokument-/Theme-Ebene erzeugen, nicht erneut im
  Shadow DOM. Komponenten konsumieren ausschließlich die bereitgestellten
  CSS Custom Properties und importieren keine Sass-Kontrastfunktion aus Base.
- Components consume `var(--nt-*)`; cross-package interoperability is CSS-token based.
- Theme repositories normally override `--nt-text` once for the standard foreground; `--nt-header` follows automatically and is only overridden for an intentional heading-specific color.
- Basis-Kontrastvordergründe über `--nt-text-on-*` konsumieren. Andere gefüllte
  Flächen müssen zum bereitgestellten Vordergrund passen; Zustandswechsel
  begründen keine zusätzlichen globalen Text-Tokens oder Komponenten-Berechnung.
- Do not emit resets, native-element styling, utility classes or component styling from style-base.
