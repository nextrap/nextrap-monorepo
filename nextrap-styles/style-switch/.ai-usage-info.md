# @nextrap/style-switch

## Purpose

Use this package for binary settings that take effect immediately. Use a checkbox for multi-select forms and a button for actions.

## Markup

```html
<label class="switch switch-material switch-lg">
  <input class="switch-input" type="checkbox" role="switch" />
  <span class="switch-control" aria-hidden="true"></span>
  <span class="switch-label">Enable notifications</span>
</label>
```

The input must precede `.switch-control`. The native checked and disabled properties are the source of truth. A visible `.switch-label`, `aria-label`, or `aria-labelledby` must provide the accessible name. Do not add static `aria-checked`; the native checkbox reflects state for `role="switch"`.

## Light/Dark theme switch

Add `.switch-theme` and place author-provided light/dark icons after the control. The icons are decorative; the input describes the switched setting. Unchecked means light and checked means dark.

```html
<label class="switch switch-theme switch-material">
  <input class="switch-input" type="checkbox" role="switch" aria-label="Dunkles Farbschema" />
  <span class="switch-control" aria-hidden="true"></span>
  <span data-switch-theme-icon="light" aria-hidden="true"><!-- sun icon --></span>
  <span data-switch-theme-icon="dark" aria-hidden="true"><!-- moon icon --></span>
</label>
```

The package styles and reorders both icon slots but deliberately does not own theme state. Application code maps the checked state to its theme mechanism, for example `data-nt-scheme="light|dark"`.

## Imports

```scss
@use '@nextrap/style-switch/default';
@use '@nextrap/style-switch' as switch;
```

`index.scss` emits no CSS. `default.scss` and `style-switch()` materialize the complete class API. Public classes and mixins have 1:1 names; base, size and visual modifier mixins stay independently composable.
