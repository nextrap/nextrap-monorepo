# SPA Header

Registriere `@nextrap/ntl-spa-header` und verwende `<ntl-spa-header>` direkt im
HTML. Das Package exportiert `NtlSpaHeader`; es benötigt keine eigene
Initialisierung, Attribute, Properties oder Events.

- `brand`, `main-nav`, `right-nav`: obere Zeile, vertikal zentrierte Slot-Inhalte.
- `sub-line`: optionale zweite Zeile über die gesamte Breite.
- `--main-line-height`: `4.5rem`; `--sub-line-height`: `2rem`.
- Parts: `main-line`, `brand`, `main-nav`, `right-nav`, `sub-line`.

Der Header setzt kein Padding, Gap oder Margin. Verwende die vorhandenen
Style-Utils an den eingesetzten Inhalten. Mehrere direkt zugewiesene rechte
Aktionen werden gemeinsam zentriert; verschachtelte Gruppen ordnen ihre Kinder
selbst an. Die Höhen sind fest; überlange Inhalte bleiben nativ scrollbar.

Leere Slots und eine vollständig leere obere Zeile verschwinden über die
bestehende Slot-Erkennung. Ein leerer zugewiesener Wrapper zählt als Belegung.
Inhalte ohne Slot-Namen bleiben als Diagnose sichtbar.

Die Anwendung kann die fertigen Styles explizit mit
`@use '@nextrap/ntl-spa-header/default';` einbinden. Alternativ materialisiert sie
`default-style()` aus der ausgabefreien Sass-API auf `ntl-spa-header.style-default`. Das Mixin nutzt die bereitgestellten NT-Tokens
für eine im hellen Theme hellgraue Fläche und eine sehr dezente innere
Schattenkante von etwa 1–2px zum Content. Die Navbar bleibt im normalen
Dokumentfluss; die Kante verschwindet mit ihr beim Scrollen und ragt nicht über
den sticky Workspace. Der JavaScript-Import lädt keine Light-DOM-Styles und
kein `style-base`.

Die HTML-Demo zeigt zusätzlich einen Header mit Login-/Kontomenü rechts.
Der Auslöser liegt direkt in `right-nav`; die native
`.dropdown-menu[popover]` folgt außerhalb des Headers. Settings,
Benutzereinstellungen und Abmelden verwenden dekorative `nte-icon`-Icons
und schließen das Beispielmenü, ohne eine echte Sitzung zu verändern.
Beide Demo-Entrys registrieren `@nextrap/nte-icon` als Demo-Abhängigkeit.
