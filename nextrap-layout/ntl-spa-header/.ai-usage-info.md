# SPA Header

Registriere `@nextrap/ntl-spa-header` und verwende `<ntl-spa-header>` direkt im
HTML. Das Package exportiert `NtlSpaHeader`; es benötigt keine eigene
Initialisierung, Attribute, Properties oder Events.

- `brand`, `main-nav`, `right-nav`: obere Zeile, vertikal zentrierte Slot-Inhalte.
- `sub-line`: optionale zweite Zeile über die gesamte Breite.
- `--main-line-height`: `4.5rem`; `--sub-line-height`: `2rem`.
- Parts: `main-line`, `brand`, `main-nav`, `right-nav`, `sub-line`.

Der Header setzt kein Padding, Gap oder Margin. Verwende die vorhandenen
Style-Utils an den eingesetzten Inhalten. Mehrere direkt zugewiesene rechte
Aktionen werden gemeinsam zentriert; verschachtelte Gruppen ordnen ihre Kinder
selbst an. Die Höhen sind fest; überlange Inhalte bleiben nativ scrollbar.

Leere Slots und eine vollständig leere obere Zeile verschwinden über die
bestehende Slot-Erkennung. Ein leerer zugewiesener Wrapper zählt als Belegung.
Inhalte ohne Slot-Namen bleiben als Diagnose sichtbar.

Die Anwendung materialisiert `default-style()` aus der Sass-API explizit auf
`ntl-spa-header.style-default`. Das Mixin nutzt die bereitgestellten NT-Tokens
für eine im hellen Theme hellgraue Fläche und einen dezenten Schatten zum
Content. Die Navbar bleibt dabei im normalen Dokumentfluss; der Schatten liegt
über dem folgenden sticky Workspace. Der JavaScript-Import lädt keine
Light-DOM-Styles und kein `style-base`.

Für HTML und die Integration vor dem SPA-Workspace lies den
[Usage-Skill](.agents/skills/ntl-spa-header-usage/SKILL.md), für visuelle
Anpassungen den [Theming-Skill](.agents/skills/ntl-spa-header-theming/SKILL.md).
