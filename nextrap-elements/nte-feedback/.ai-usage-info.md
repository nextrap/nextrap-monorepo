# @nextrap/nte-feedback

Für SPAs ist die zentrale Integration mit `@trunkjs/api-stub` der
Standard für API-Ladezustände und Backend-Fehler. `<nte-feedback>` einmal
in der App-Shell einbinden. Keine individuellen Loading-/Error-Wrapper
und keine Catch-Blöcke nur zur Fehleranzeige in Pages oder Komponenten.

```ts
import { Feedback } from '@nextrap/nte-feedback';
import { API as generatedAPI } from './generated-api';

export const API = generatedAPI.with(Feedback.createRequestHandler());

await API.File.Get.request({ params: { id: 'index.md' } });
await API.File.Save.request({
  params: { id: 'index.md' },
  body: { content: '# Startseite' },
  feedback: { key: 'dialog', name: 'Datei speichern' },
});
```

Standardmäßig erscheint nur der Mini-Balken; Dialog-Requests zeigen bei
Erfolg den Namen. Backend-Fehler werden zentral mit Name und Fehlerdetails
angezeigt. `feedback` erlaubt key, name, loadingMessage, successMessage,
errorMessage und data (z. B. `{ details: 'index.md' }`).
`feedback: false` deaktiviert Loading, nicht die Fehleranzeige.
`reportError: false` deaktiviert den globalen Error-Callback. Fehler
werden weiterhin geworfen; Abbrüche werden nicht als Fehler angezeigt.
Die benötigten Stub-Callbacks stammen aus
[TrunkJS PR #49](https://github.com/trunkjs/trunkjs-monorepo/pull/49).

Manuell für Nicht-API-Aktionen: `Feedback.loading`, `ready`, `progress`,
`success`, `error` / `fail`, `info`, `alert`, `confirm`, `close`, `open`.
`alert()` und `confirm()` ersetzen Browser-Dialoge; öffnende Methoden
lösen beim Schließen auf. Manuelle Aufrufe ersetzen das aktive Feedback.

Siehe [README](README.md) und [SPA-Demo](demo/01-usage.md).
