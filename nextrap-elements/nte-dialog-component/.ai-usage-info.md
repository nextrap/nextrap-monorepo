# AI usage information: @nextrap/nte-dialog-component

Use this package for typed, programmatic dialogs in applications and SPAs.

For Markdown, CMS content, static/declarative HTML, launcher slots, URL hash/anchor opening, or direct use of a dialog element, use `@nextrap/nte-dialog` instead.

## Architecture

`NteDialogComponent<TInput, TResult>` is an application abstraction built on `@nextrap/nte-dialog`. It owns:

- temporary mounting into `document.body` via static `show()`
- typed input
- Promise-based typed results
- `submit()` / `abort()` completion
- rendering title/body/footer into an inner `NteDialog`
- cleanup after completion
- re-exporting dialog Shadow DOM parts through `exportparts`

It does not own launcher, anchor/hash routing, native dialog rendering, backdrop handling or visual Sass implementation. Those belong to `@nextrap/nte-dialog`.

## Basic pattern

```ts
class UserEditDialog extends NteDialogComponent<{ userId: string }, User> {
  protected override renderTitle() {
    return html`Edit user`;
  }

  protected override renderDialog() {
    return html`<user-editor .userId=${this.input.userId}></user-editor>`;
  }

  protected override renderFooter() {
    return html`
      <button @click=${this.abort}>Cancel</button>
      <button @click=${() => this.submit(user)}>Save</button>
    `;
  }
}

const result = await UserEditDialog.show({ userId: '123' });
if (result.submitted) {
  use(result.data);
}
```

## Result contract

```ts
type NteDialogComponentResult<T> =
  | { submitted: true; data: T }
  | { submitted: false };
```

Keep `submitted` as the discriminator. Do not add parallel `aborted`, `saved`, or status-enum fields without intentionally redesigning the public API.

## Void input and result

Both generics default to `void`:

```ts
class ConfirmDialog extends NteDialogComponent { ... }
const result = await ConfirmDialog.show();
```

For `TResult = void`, use `this.submit()` with no dummy payload.

## Rendering contract

Derived classes override:

- `renderDialog()` — required body content
- `renderTitle()` — optional title
- `renderFooter()` — optional footer/actions

The base class owns `render()` so that mounting, dismiss mapping, slots and Shadow DOM part forwarding remain consistent.

## Options

```ts
protected override dialogOptions = {
  dialogClass: ['size-lg', 'with-shadow'],
  dismiss: {
    closeButton: true,
    escape: true,
    backdrop: 'shake',
  },
};
```

`dialogClass` is the bridge to the visual API from `@nextrap/nte-dialog`. Keep visual concerns such as size, shadow and highlighted appearance in CSS/Sass rather than adding TypeScript behavior options.

`dismiss` controls application-level dismiss behavior. An accepted dismiss resolves the dialog through `abort()`.

## Shadow DOM

The component nests `NteDialog` in its Shadow DOM. Preserve `exportparts="dialog,header,content,footer,close-button"` so consumers can style the underlying dialog through both shadow boundaries.

## Cross-package guidance

Use `@nextrap/nte-dialog-component` when the requirement contains concepts such as:

- open a dialog from TypeScript/application code
- typed input
- await a result
- Promise
- submit/cancel result
- SPA workflow

Use `@nextrap/nte-dialog` when the requirement contains concepts such as:

- Markdown or CMS page
- declarative HTML
- launcher/opener element
- `#modal:...` anchor
- direct `<nte-dialog>` markup

Do not add launcher or anchor APIs to this package. If such behavior is needed, compose/use `NteDialog` directly.

When changing the public programmatic API, update this file and the README examples together.
