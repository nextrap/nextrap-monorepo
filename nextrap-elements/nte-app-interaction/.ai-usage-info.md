# @nextrap/nte-app-interaction

## Purpose

Global application interaction channel for Nextrap applications. It handles both messages and questions; its public responsibility is not tied to a dialog, overlay or toast presentation.

The maintained package usage index is [`skills/nte-app-interaction-usage/SKILL.md`](skills/nte-app-interaction-usage/SKILL.md); the Demo Viewer examples under `demo/*.demo.ts` are the executable reference.

It is meant to be mounted once on the page and then controlled through global `window` custom events with the `nextrap:` prefix.

## Styling

Default visual styling is provided by the exported Sass API:

```scss
@use '@nextrap/nte-notifier' as notifier;

nte-notifier.style-default {
  @include notifier.default-style();
}
```

The package also ships `default.scss`, which binds `default-style()` to `nte-notifier.style-default`. `SetDefaultStyleMixin` adds `style-default` automatically when no other `style-*` class exists. Keep Shadow DOM styles functional only and style the component through CSS variables and public parts such as `dialog`, `panel`, `headline`, `message`, `spinner`, `progress-bar`, `progress-value`, `details`, `html`, `close-button` and `button` / `button-*`.

## Mounting

Mount it once, usually directly in `body`:

```html
<body>
  <nte-app-interaction></nte-app-interaction>
</body>
```

Do not use it as a wrapper around page content.

## Construction rule

This is an `nte-*` element and should follow the shared `@nextrap/nt-core` conventions.
The component itself uses `nextrap_element({ eventBinding: true })` and `@Listen(..., { target: 'window' })` for global events.

## Event model

Supported global events:

- `nextrap:loading`
- `nextrap:progress`
- `nextrap:success`
- `nextrap:fail`
- `nextrap:info`
- `nextrap:confirm`

## Common usage examples

### Progress / wait dialog

```ts
window.dispatchEvent(
  new CustomEvent('nextrap:progress', {
    detail: {
      title: 'Datei-Upload',
      progress: 45,
      message: 'Dateien werden verarbeitet...',
      cancelable: true,
    },
  }),
);
```

If `title` is omitted, the app interaction falls back to the default status title.

### Error dialog with expandable details

```ts
window.dispatchEvent(
  new CustomEvent('nextrap:fail', {
    detail: {
      message: 'Import fehlgeschlagen.',
      details: 'Zeile 152: Ungültiges Datumsformat in Spalte "deliveryDate".',
      autoClose: false,
      cancelable: true,
    },
  }),
);
```

### Confirm dialog

```ts
window.dispatchEvent(
  new CustomEvent('nextrap:confirm', {
    detail: {
      message: 'Wirklich löschen?',
      cancelable: true,
      actions: [
        {
          label: 'Löschen',
          variant: 'danger',
          callback: () => console.log('confirmed'),
        },
      ],
    },
  }),
);
```

## Accessibility behavior

- The app interaction renders a native `<dialog>`.
- Loading and progress states are announced as wait dialogs for screen readers.
- Confirm states are announced as prompt / confirmation dialogs.
- Error details are rendered in a native `<details><summary></summary></details>` block.
- If `cancelable: true` is set, the dialog shows a close button (`×`) and reacts to ESC / cancel.

## Presentation boundary

Keep `nte-app-interaction` as the single global event coordinator. The current native dialog is one presenter. A future toast presenter should be implemented separately and delegated to for non-blocking messages; it must not introduce a competing global event API. Confirmation questions and cancelable/blocking operations remain modal.

The dialog presenter consumes inherited `@nextrap/style-base` tokens directly for its raised surface, text, border, radius and blurred backdrop. Do not redeclare those theme colors on the host or introduce component-specific color fallbacks. Shadow DOM action buttons use only the required `@nextrap/style-button` mixins. Backdrop clicks dismiss passive messages and shake interactions that require a selection or cannot be canceled.
