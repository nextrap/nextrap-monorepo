# @nextrap/nte-card

Card layout web component with optional header, image, content, footer and link slot handling.

## Import

```ts
import '@nextrap/nte-card';
```

For styling:

```scss
@use '@nextrap/nte-card' as card;
```

## Usage

```html
<nte-card class="img-overlay">
  <h3 slot="header">Title</h3>
  <img slot="image" src="/image.jpg" alt="">
  <p>Card content</p>
  <p slot="footer">Footer</p>
</nte-card>
```

Direct images or `p:has(img:not(.keep))` can be assigned to the `image` slot. Use `--aspect-ratio` or `--image-aspect-ratio` on `nte-card` to control the image area ratio. A hidden `link` slot can make the whole card clickable when it contains an empty `a[href]`.

## Parts

Use `::part(wrapper)`, `::part(header)`, `::part(image)`, `::part(gradient)`, `::part(content)`, `::part(footer)` and `::part(link)` for Light DOM/theme styling.

## Mixins

```scss
@include card.default-style(
  $innerPadding: var(--nt-space-3),
  $border: 1px solid var(--nt-primary),
  $background-color: unset,
  $border-radius: var(--nt-border-radius),
  $image-aspect-ratio: 16 / 9,
  $overlay-background: linear-gradient(to top, rgba(0, 0, 0, 0.55), transparent),
  $modifierClasses: true,
  $gap: var(--nt-text-gap)
);
@include card.with-region-bleed(image);
@include card.with-region-bleed(header, inline);
@include card.with-image-fullsize();
@include card.with-image-overlay();
@include card.with-modifier-classes();
```

`default-style()` bindet genau ein Wrapper-Padding und einen unabhängigen Regions-Gap. Image, Header, Content und Footer addieren kein Layout-Padding; leere Slots erzeugen keinen Gap, eine vollständig leere Card keinen Rahmen. Header und Footer liegen innerhalb des Card-Rahmens. Der versteckte Link-Slot ist keine Layout-Region. `--inner-padding` und `--gap` werden pro Card initialisiert; der Gap des Elternlayouts wird nicht geerbt. Content darf für gleiche Kartenhöhen wachsen: zusätzlicher freier Raum innerhalb Content ist kein größerer Regions-Gap.

## Randlose Regionen

`with-region-bleed($region: image, $edges: all)` erweitert eine Region bis zur inneren Rahmenkante. Regionen: `image`, `header`, `content`, `footer`. Kanten: `all`, `inline`, `block`, `inline-start`, `inline-end`, `block-start`, `block-end`; auch Listen sind möglich. Ungültige Namen erzeugen einen Sass-Fehler. Bleed erwartet einen einzelnen CSS-Längenwert in `--inner-padding`, keine mehrwertige Padding-Kurzform.

Block-Bleed wirkt nur an der ersten/letzten sichtbaren Region des normalen Card-Stacks. Fehlende Slots werden dynamisch berücksichtigt. Ein einzelnes Titelbild mit Image-Bleed liegt daher an allen vier Rahmenkanten, während ein Titelbild über Text oben und seitlich randlos bleibt und zum Text ausschließlich Gap behält. Keine Padding-Ausnahme durch automatische Bilderkennung: Die Theme-Komposition oder Helper-Klasse wählt Bleed ausdrücklich.

Für eine eigene horizontale Grid-Komposition muss das Theme deren äußere Kanten explizit definieren: `--_nte-card-first` und `--_nte-card-last` an betroffenen Parts beschreiben die Blockkanten; die Spalten-Innenkante darf keinen negativen Bleed-Margin erhalten. Die Flags sind interne Kompositionswerte, keine Autoren-API. Die geprüfte Featured-Story in ThemeJS2 zeigt die Komposition.

## Helper und Overlays

Der Default registriert unter dem aktuellen Style-Selektor `.with-image-fullsize` / `.img-fullsize`, `.with-image-overlay` / `.img-overlay`, `.with-region-bleed` (Image) sowie `.with-image-bleed`, `.with-header-bleed`, `.with-content-bleed`, `.with-footer-bleed`. `$modifierClasses: false` oder `none` deaktiviert die gesamte Registrierung. Direkte Mixins werden nach der vollständigen Baseline eingebunden.

Overlay verwendet eine gemeinsame **randlose** Bild-/Content-Fläche; Content erhält dort einen bewussten Textschutz mit `--inner-padding`. Zwischen überlagerten Flächen gibt es keinen Gap. Header und Footer folgen außerhalb dieser Medienfläche, aber innerhalb des Rahmens. Ohne Bild fällt Overlay auf die normale Card-Darstellung zurück. Die abgeleitete, schreibgeschützte Zustandsoberfläche `data-card-regions` enthält die belegten Regionen als Tokens; Autoren setzen dieses Attribut nicht. Themes können damit Grid-Tracks ohne Phantom-Zeilen abbilden, auch bei reinem Text im Default-Slot.

Fullsize bleibt unabhängig von Bleed und löst nur die feste Bild-Aspect-Ratio. Eigene Margins slottierter Inhalte sind weiterhin Typografie beziehungsweise Inhaltsgestaltung und werden nicht global zurückgesetzt. Der reine Sass-Entrypoint erzeugt kein CSS; visuelle Rahmen-/Background-Defaults werden über `default-style()` eingebunden.
