# AI usage information: @nextrap/nte-dialog

Use this package for declarative website/content dialogs: Markdown, CMS content, static HTML, launcher/opener markup, URL anchor routing, or direct manipulation of an existing `<nte-dialog>` element.

For application/SPAs where TypeScript creates a temporary dialog, passes typed input and awaits a typed Promise result, use `@nextrap/nte-dialog-component` instead.

## Responsibilities

`NteDialog` owns:

- the native `<dialog>` element
- launcher/opener slot
- automatic Markdown-friendly slot assignment
- title/content/footer slots
- close button, Escape and backdrop behavior
- `show()`, `showModal()` and `close()`
- optional `#modal:...` URL hash integration
- Shadow DOM parts
- the public Sass styling/mixin API

It does not own typed application input/output, Promise results, `submit()` / `abort()`, or temporary mounting. Those belong to `@nextrap/nte-dialog-component`.

## Launcher / opener

```html
<nte-dialog>
  <button class="launcher">Open</button>
  <h2>Title</h2>
  <p>Content</p>
  <div class="footer">Footer</div>
</nte-dialog>
```

The launcher slot is inside the `NteDialog` Shadow DOM but outside the native `<dialog>`, so it remains visible while the dialog is closed. An empty launcher slot renders no visible opener.

Automatic light-DOM assignment follows Nextrap's `SubLayoutApplyMixin` / `data-query` convention:

- `.launcher` or `[data-dialog-launcher]` -> `launcher`
- direct `h1` through `h5` -> `title`
- `.footer` or `[data-dialog-footer]` -> `footer`
- unassigned content -> default slot

Explicit `slot` attributes remain supported.

## Anchor / hash

```html
<nte-dialog id="help" anchor>...</nte-dialog>
```

maps to `#modal:help`.

```html
<nte-dialog id="internal-help" anchor="help">...</nte-dialog>
```

also maps to `#modal:help`. An explicit non-empty anchor string always wins over `id`.

When the matching hash appears, the dialog opens. When an anchor-opened dialog loses the matching hash, it closes. Closing a dialog while its modal hash is active removes that hash. A launcher on an anchor-enabled dialog should activate the hash instead of bypassing the route.

## Direct DOM API

```ts
const dialog = document.getElementById('help') as NteDialog;
dialog.showModal();
await dialog.close();
```

If the requirement additionally needs typed input/output or an awaited result, switch to `@nextrap/nte-dialog-component` rather than building that lifecycle around this element manually.

## Dismiss behavior

- `no-dismiss`: prevent all user-initiated dismiss actions
- `hide-close-button`: do not render the default close button
- `no-escape`: prevent Escape dismissal
- `backdrop-action="ignore|shake|dismiss"`: configure backdrop clicks

A dismiss attempt emits a cancelable `dismiss` event with `detail.reason` equal to `close-button`, `escape`, or `backdrop`.

## Animation compatibility strategy

Opening uses CSS transitions together with `@starting-style`. Closing currently uses an explicit `.closing` state and waits for the dialog's `opacity` `transitionend` before calling native `dialog.close()`. Do not replace this with a fixed JavaScript timeout; themes may change the transition duration. A computed-duration timeout is used only as a defensive fallback if the transition event is lost.

This hybrid exit path is intentional for browser interoperability. Native discrete `display` / top-layer (`overlay`) exit transitions are not yet sufficiently interoperable across the supported Chromium, Safari and Firefox browser set. Revisit this implementation as browser support evolves. Once all supported browsers, including Firefox, reliably keep modal `<dialog>` elements in the top layer for a complete CSS-only exit transition, remove the `.closing` / `transitionend` JavaScript fallback and use the native discrete CSS transition path instead.

Respect `prefers-reduced-motion`; the component closes immediately when reduced motion is requested.

## Styling contract

Keep behavior in TypeScript and appearance in Sass/CSS. Do not add TypeScript options for visual size, shadow, highlighted appearance or similar visual concerns.

Public modifier classes and Sass mixins have matching names:

- `.style-default` <-> `style-default()`
- `.style-highlighted` <-> `style-highlighted()`
- `.size-sm` <-> `size-sm()`
- `.size-md` <-> `size-md()`
- `.size-lg` <-> `size-lg()`
- `.size-xl` <-> `size-xl()`
- `.size-fullscreen` <-> `size-fullscreen()`
- `.with-shadow` <-> `with-shadow()`
- `.without-shadow` <-> `without-shadow()`
- `.with-floating-header` <-> `with-floating-header()`

The package `index.scss` exposes mixins without emitting classes. `default.scss` emits the standard class set through `dialog-styles()`.

Prefer composing mixins in semantic application styles:

```scss
@use '@nextrap/nte-dialog' as dialog;

.product-dialog {
  @include dialog.style-default();
  @include dialog.size-lg();
  @include dialog.with-shadow();
}
```

## Shadow DOM parts

`NteDialog` exposes `dialog`, `header`, `content`, `footer`, and `close-button` parts. Preserve these public part names.

## Cross-package guidance

Use this package when the request mentions Markdown, CMS, declarative HTML, launcher/opener, anchor/hash routing or an existing `<nte-dialog>`.

Use `@nextrap/nte-dialog-component` when the request mentions SPA/application code, typed input, Promise result, `submit()`/`abort()`, or creating a dialog from anywhere in TypeScript.

When adding a new public opening mode, behavioral option, slot convention or styling modifier, update this file, README and `demo/base.md` together.
