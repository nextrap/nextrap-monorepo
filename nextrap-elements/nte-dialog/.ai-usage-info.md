# AI usage information: @nextrap/nte-dialog

Use this package for declarative website/content dialogs: Markdown, CMS content, static HTML, launcher/opener markup, URL anchor routing, or direct manipulation of an existing `<nte-dialog>` element.

For application/SPAs where TypeScript creates a temporary dialog, passes typed input and awaits a typed Promise result, use `@nextrap/nte-dialog-component` instead.

## Responsibilities

`NteDialog` owns the native `<dialog>`, launcher/opener, Markdown-friendly title/content/footer classification, dismiss behavior, `show()` / `showModal()` / `close()`, optional `#modal:...` routing, Shadow DOM parts, and the Sass styling API. Typed application input/output, Promise results, `submit()` / `abort()` and temporary mounting belong to `@nextrap/nte-dialog-component`.

## Launcher / opener

```html
<nte-dialog>
  <button class="launcher">Open</button>
  <h2>Title</h2>
  <p>Content</p>
  <div class="footer">Footer</div>
</nte-dialog>
```

Automatic direct light-DOM assignment:

- `.launcher` or `[data-dialog-launcher]` -> `launcher`
- direct `h1` through `h5` -> `title`
- `.footer` or `[data-dialog-footer]` -> `footer`
- unassigned content -> default slot

## Anchor / hash

`<nte-dialog id="help" anchor>` maps to `#modal:help`. `<nte-dialog id="internal-help" anchor="help">` also maps to `#modal:help`; an explicit non-empty anchor string wins over `id`. Closing removes an active modal hash, and launcher clicks on anchor-enabled dialogs activate the hash route.

## Direct DOM API

```ts
const dialog = document.getElementById('help') as NteDialog;
dialog.showModal();
await dialog.close();
```

If typed input/output or an awaited result is required, switch to `@nextrap/nte-dialog-component`.

## Dismiss behavior

- `no-dismiss`: prevent all user-initiated dismiss actions
- `hide-close-button`: do not render the default close button
- The default control uses the shared `@nextrap/style-elements` `close-btn()` pattern and `--nt-icon-close`.
- `no-escape`: prevent Escape dismissal
- `backdrop-action="ignore|shake|dismiss"`: configure backdrop clicks

A dismiss attempt emits a cancelable `dismiss` event with `detail.reason` equal to `close-button`, `escape`, or `backdrop`.

## Animation compatibility strategy

Opening uses CSS transitions together with `@starting-style`. Closing uses an explicit `.closing` state and waits for the dialog's `opacity` `transitionend` before native `dialog.close()`. Do not replace this with a fixed JavaScript timeout. The computed-duration timeout is defensive only.

This hybrid path remains until supported Chromium, Safari and Firefox versions reliably support a complete CSS-only modal `<dialog>` exit including discrete display/top-layer behavior. Once that is interoperable, remove the `.closing` / `transitionend` fallback and use native discrete CSS transitions. Respect `prefers-reduced-motion`.

## Styling contract

Keep behavior in TypeScript and appearance in Sass/CSS. Public modifier classes and Sass mixins have matching names: `style-default`, `style-highlighted`, `size-sm`, `size-md`, `size-lg`, `size-xl`, `size-fullscreen`, `with-shadow`, `without-shadow`, and `with-floating-header`.

Without a `style-*` variant, the native dialog and its sections remain transparent and inherit their text color. The selected variant or consuming theme owns the visible surface; `style-default()` maps it to `--nt-surface-raised` and `--nt-text`.

```scss
@use '@nextrap/nte-dialog' as dialog;

.product-dialog {
  @include dialog.style-default();
  @include dialog.size-lg();
  @include dialog.with-shadow();
}
```

`NteDialog` exposes `dialog`, `header`, `content`, `footer`, and `close-button` parts. Preserve these names.

## Cross-package guidance

Use this package for Markdown, CMS, declarative HTML, launcher/opener, anchor/hash routing or an existing `<nte-dialog>`. Use `@nextrap/nte-dialog-component` for SPA/application code, typed input, Promise results, `submit()`/`abort()`, or creating a dialog from TypeScript.

The live Demo Viewer example is `demo/01-modal.demo.ts`, with its Markdown content in `demo/01-modal.md`.

When adding a public opening mode, behavioral option, slot convention or styling modifier, update this file, README, `demo/base.md` and the live demo together.
