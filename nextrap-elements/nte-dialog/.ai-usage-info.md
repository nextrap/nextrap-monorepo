# AI usage information: @nextrap/nte-dialog

Use this file as the implementation and usage contract when generating code that uses or modifies `@nextrap/nte-dialog`.

## Architecture

The package intentionally has two layers:

1. `NteDialog` is the reusable UI primitive. It owns the native `<dialog>`, slots, launcher, dismiss behavior, animations, parts and optional URL hash integration.
2. `NteModalComponent<TInput, TResult>` is the programmatic application abstraction. It owns temporary mounting, typed input/output, Promise completion and cleanup and renders an `NteDialog` internally.

Do not move launcher or anchor behavior into `NteModalComponent`. They are declarative-document features of `NteDialog`.

## Choose the correct opening pattern

### Declarative launcher / opener

Use this for Markdown/HTML pages where a visible element should open the dialog without custom JavaScript.

```html
<nte-dialog>
  <button class="launcher">Open</button>
  <h2>Title</h2>
  <p>Content</p>
  <div class="footer">Footer</div>
</nte-dialog>
```

The launcher slot is outside the native dialog. Do not put a launcher API on `NteModalComponent`.

Automatic light-DOM assignment follows the `SubLayoutApplyMixin` / `data-query` convention used by Nextrap content components:

- `.launcher` or `[data-dialog-launcher]` -> `launcher`
- direct `h1` through `h5` -> `title`
- `.footer` or `[data-dialog-footer]` -> `footer`
- unassigned content -> default slot

Explicit `slot` attributes remain valid and should be preferred when generated markup already has semantic slot information.

### Anchor / hash

Use `anchor` only when the dialog should be addressable through the URL.

```html
<nte-dialog id="help" anchor>...</nte-dialog>
```

maps to `#modal:help`.

```html
<nte-dialog id="internal-help" anchor="help">...</nte-dialog>
```

also maps to `#modal:help`. An explicit anchor string always wins over `id`.

When the active modal hash appears, the component opens itself. When an anchor-opened dialog loses the matching hash, it closes. Closing a dialog with its modal hash active removes that hash.

### Direct DOM API

For an existing element, call the component directly:

```ts
const dialog = document.getElementById('help') as NteDialog;
dialog.showModal();
await dialog.close();
```

### Programmatic application modal

Use `NteModalComponent<TInput, TResult>` when a caller needs typed input and a Promise result from a temporary dialog.

```ts
class UserEditDialog extends NteModalComponent<{ userId: string }, User> {
  protected override renderTitle() {
    return html`Edit user`;
  }

  protected override renderModal() {
    return html`...`;
  }

  save(user: User) {
    this.submit(user);
  }
}

const result = await UserEditDialog.show({ userId: '123' });
if (result.submitted) {
  use(result.data);
}
```

The result type is deliberately discriminated by the boolean `submitted`:

```ts
type NteModalResult<T> =
  | { submitted: true; data: T }
  | { submitted: false };
```

Use `submit(data)` for successful completion and `abort()` for cancellation. Do not introduce separate `aborted`, `saved`, or status enum fields unless the public API is intentionally redesigned.

## Rendering contract for NteModalComponent

Derived components override:

- `renderTitle()` for title content
- `renderModal()` for body content
- `renderFooter()` for footer/actions

`render()` is owned by the base class so it can wrap these sections in `nte-dialog`. Prefer extending the section methods instead of replacing the wrapper lifecycle.

`modalOptions` configures behavior and classes:

```ts
protected override modalOptions = {
  dialogClass: ['size-lg', 'with-shadow'],
  dismiss: {
    closeButton: true,
    escape: true,
    backdrop: 'shake',
  },
};
```

`dialogClass` is intentionally styling-oriented. Behavioral options should not be encoded as styling classes.

## Dismiss behavior

`NteDialog` supports:

- `no-dismiss`: prevent all user initiated dismiss actions
- `hide-close-button`: do not render the default close button
- `no-escape`: ignore Escape and shake instead
- `backdrop-action="ignore|shake|dismiss"`: configure backdrop clicks

A dismiss attempt emits a cancelable `dismiss` event with `detail.reason` equal to `close-button`, `escape`, or `backdrop`. `NteModalComponent` maps an accepted dismiss to `abort()`.

## Styling contract

Keep behavior in TypeScript and appearance in Sass/CSS. Do not add TypeScript options for visual size, shadow, highlighted appearance, or similar visual concerns.

Public modifier classes and public Sass mixins have matching names:

- `.style-default` <-> `style-default()`
- `.style-highlighted` <-> `style-highlighted()`
- `.size-sm` <-> `size-sm()`
- `.size-md` <-> `size-md()`
- `.size-lg` <-> `size-lg()`
- `.size-xl` <-> `size-xl()`
- `.size-fullscreen` <-> `size-fullscreen()`
- `.with-shadow` <-> `with-shadow()`
- `.without-shadow` <-> `without-shadow()`
- `.with-floating-header` <-> `with-floating-header()`

The package `index.scss` exposes mixins without emitting classes. `default.scss` emits the standard class set through the aggregate `dialog-styles()` mixin.

Prefer composing mixins in semantic application styles:

```scss
@use '@nextrap/nte-dialog' as dialog;

.user-editor {
  @include dialog.style-default();
  @include dialog.size-lg();
  @include dialog.with-shadow();
}
```

The Shadow DOM stylesheet should contain structural behavior and consume CSS custom properties. Public visual styling should remain possible from the light DOM through the host classes/mixins.

## Shadow DOM and parts

`NteDialog` exposes these parts:

- `dialog`
- `header`
- `content`
- `footer`
- `close-button`

`NteModalComponent` nests `NteDialog` in its own Shadow DOM and re-exports these parts using `exportparts`. Preserve that forwarding when changing the wrapper so consumers can style through both shadow boundaries.
