# @nextrap/nte-input

## Purpose

`nte-input` is the shared form-control frame for label, control chrome, validation and optional input aid. Concrete controls are provided by statically registered plugins.

Built-in types include text/email/password, textarea, select, select-radio, checkbox and token-input.

## Public API

Common host attributes/properties:

- `type`
- `label`
- `placeholder`
- `data-options`
- `value`
- `multiple`
- `required`
- `disabled`
- `validation-message`
- `invalid` / `valid`

Named slots:

- `start`
- `end`
- `validation`
- `input-aid`

The element is form-associated and participates in native `FormData`. Use `FormDataAccessor` from `@trunkjs/browser-utils` for object-based form access.

## Plugin architecture

Register one plugin class per supported input type. A type may only be registered once.

```ts
class MyPlugin extends AbstractNteInputPlugin {
  static readonly types = ['my-type'];

  render(context: NteInputRenderContext) {
    return html`...`;
  }
}

NteInput.registerPlugin(MyPlugin);
```

Plugins own type-specific markup, value handling, validity and optional plugin styles. The base component owns the common frame and reflected states such as `has-value`, `has-placeholder` and `hoverlabel-active`.

## Styling

The package exports theme, floating-label, select-radio and size mixins.

```scss
@use '@nextrap/nte-input' as input;

nte-input.default {
  @include input.default-style(input.$themeBootstrap);
}

nte-input.carbon {
  @include input.default-style(input.$themeCarbon);
}

nte-input.hoverlabel {
  @include input.floating-labels();
}
```

`$themeBootstrap` and `$themeCarbon` own the complete visual baseline. Carbon geometry is intentionally different, but colors are derived from semantic Nextrap tokens so both themes work in light and dark schemes.

`floating-labels()` is a composable modifier. It only positions the label and must not change the control height, vertical padding or other theme-owned geometry. It consumes theme-exported custom properties such as `--nte-input-control-padding-x` and `--nte-input-hoverlabel-background`, so the same modifier can adapt automatically to the active style.

See `ARCHITECTURE.md` for the binding contract between styles and modifiers. Generic modifiers must not contain constants that only work for one visual style; use theme-exported `--nte-input-*` values or explicitly scope the modifier to supported style variants.

## Dark theme

Use semantic tokens (`--nt-text`, `--nt-body`, `--nt-primary`, `--nt-danger`, `--nt-success`, `--nt-border-color`, etc.) for theme-reactive colors. Avoid fixed light surfaces in component themes unless the value is intentionally invariant and documented.

## Hoverlabel states

The floating label is active while the control is focused or when the host reflects `has-value`, `has-placeholder`, `placeholder` or `hoverlabel-active`.

The label moves to the upper control edge without moving the actual input content. Plugins can force the active state via `isHoverlabelActive()`.

## Built-in value shapes

- text/email/password/textarea/select: `string`
- checkbox: `boolean`
- select-radio: `string[]`
- token-input: `string[]`

## Options

`data-options` supports semicolon syntax such as `draft|Entwurf;active|Aktiv` and JSON. Select, select-radio and token-input can alternatively resolve an `<options>` child when no `data-options` are present.
