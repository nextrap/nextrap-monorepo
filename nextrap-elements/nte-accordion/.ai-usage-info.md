# @nextrap/nte-accordion

Accordion element web component for embedded FAQ/detail sections.

## Import

```ts
import '@nextrap/nte-accordion';
```

For styling:

```scss
@use '@nextrap/nte-accordion' as accordion;
```

## Usage

```html
<nte-accordion initial-open-index="0" marker-position="end">
  <section>
    <h3>Question</h3>
    <p>Answer text.</p>
  </section>
</nte-accordion>
```

In Markdown/content-pane layouts, put `layout="nte-accordion"` on the parent section; direct child sections become `nte-accordion-item`. Demo/theme SCSS binds the visual baseline to `nte-accordion.style-default`.

## Behavior

- Pairing demo `demo/pairing-accordion.md` shows `nte-accordion` inside `ntl-2col` main/aside columns.
- `nte-accordion` converts direct `section:not(.keep)` children to `nte-accordion-item` via `SubLayoutApplyMixin`.
- Each item moves its first direct heading into the `title` slot.
- `initial-open-index` opens one item on first render (`initial-open-index` without value means `0`).
- `exclusive` closes other items when a new item opens.
- `marker-position="start|end"` and `marker-icon="chevron|plus"` on the accordion are propagated to items unless an item already defines the attribute.
- Accordions are usually embedded in parent layouts/cards; do not add external margins in the component or default mixin.

## Parts

Accordion: `accordion`.

Item: `details`, `summary`, `title`, `marker`, `content`.

## Default style and interaction contract

`default-style()` follows the global `@nextrap/style-base` runtime contract. Its defaults use semantic design tokens rather than local hard-coded design values:

- border: `--nt-border-width` + `--nt-border`
- radius: `--nt-border-radius`
- summary padding: `--nt-spacing-control`
- content padding: `--nt-spacing-component`
- summary surface: `--nt-surface-muted`
- summary text: `--nt-text`
- focus: `--nt-focus`
- hover intensity: `--nt-interaction-hover`
- active intensity: `--nt-interaction-active`
- transition duration: `--nt-transition-duration`
- transition easing: `--nt-transition-easing`

The accordion must not introduce its own fixed hover/active percentages or transition times. This is the standard for other interactive Nextrap elements as well: buttons, tabs, navigation, clickable cards, menus and future hoverable controls should consume the shared style-base interaction tokens. Component-specific mixin arguments are override hooks, not a second design-token system.

For a custom summary surface, the default hover/active states are calculated from that local surface using the shared global interaction intensities. This means `$summary-background` can be changed without having to manually redefine its hover and active variants unless the design intentionally requires exceptional colors.

## Mixins

```scss
@include accordion.default-style(
  $item-gap: 0,
  $border: var(--nt-border-width, 1px) solid var(--nt-border),
  $border-radius: var(--nt-border-radius),
  $summary-padding: var(--nt-spacing-control),
  $content-padding: var(--nt-spacing-component),
  $summary-background: var(--nt-surface-muted),
  $summary-background-hover: color-mix(in oklch, var(--summary-background), light-dark(black, white) var(--nt-interaction-hover)),
  $summary-background-active: color-mix(in oklch, var(--summary-background), light-dark(black, white) var(--nt-interaction-active)),
  $summary-color: var(--nt-text),
  $content-background: transparent,
  $marker-size: 1.25rem,
  $marker-color: currentColor,
  $focus-outline: 2px solid var(--nt-focus),
  $transition-duration: var(--nt-transition-duration),
  $transition-easing: var(--nt-transition-easing),
  $modifierClasses: true
);
@include accordion.with-details-end();
@include accordion.with-marker-start();
@include accordion.with-marker-plus();
@include accordion.with-modifier-classes();
```

`default-style()` includes the `.details-end`, `.marker-start` and `.marker-plus` modifier classes by default. Visual styling belongs in these mixins or theme SCSS; Shadow DOM CSS should stay functional only.
